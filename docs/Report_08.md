**Тема**  
Автоматизація збирання та запуску тестів ATCsim за допомогою GitHub Actions.

**Мета**  
Налаштувати автоматичне збирання й тестування ATCsim за допомогою GitHub Actions і перевірити команди робочого процесу на Windows.

## 1. Початковий стан проєкту

Рішення `ATCsim.sln` містить проєкти `ATCsim.Core`, `ATCsim.Data`, `ATCsim.UI` і `ATCsim.Tests`. Збирання всього рішення перевіряє також WPF-проєкт `ATCsim.UI`, який має цільову платформу `net10.0-windows`. Проєкт `ATCsim.Tests` містить модульні тести xUnit і інтеграційні тести зі SQLite. Для збирання та тестування обрано одну конфігурацію `Release` і середовище Windows із .NET SDK 10. [Інструкція зі збирання ATCsim](../README.md#збірка-з-вихідного-коду).

Перед налаштуванням 25 листопада 2026 року у вихідній версії репозиторію не було конфігурації CI. Публічний API GitHub на той час показав нуль зареєстрованих робочих процесів і нуль запусків для ATCsim. [Робочі процеси](https://api.github.com/repos/dyxell1n/ATCsim/actions/workflows), [запуски](https://api.github.com/repos/dyxell1n/ATCsim/actions/runs).

## 2. Конфігурація GitHub Actions

Додано файл [`.github/workflows/ci.yml`](../.github/workflows/ci.yml). Робочий процес `CI` запускається після оновлення будь-якої гілки та для запитів на злиття до `main`. Завдання `Build and test (Windows)` виконується на `windows-2025`, щоб зібрати застосунок WPF. Дії `actions/checkout` і `actions/setup-dotnet` прив’язані до конкретних комітів відповідних випусків. Робочий процес має дозвіл на читання вмісту репозиторію. [Середовища виконання GitHub Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job), [збирання і тестування .NET у GitHub Actions](https://docs.github.com/en/actions/tutorials/build-and-test-code/net).

Після отримання вихідного коду та налаштування .NET SDK `10.0.x` команда `dotnet build` відновлює залежності NuGet і компілює рішення у конфігурації `Release`. Наступна команда запускає xUnit із параметром `--no-build` для перевірки вже зібраних файлів. У разі помилки збирання завдання завершується до запуску тестів. Невдалий тест також позначає завдання як неуспішне.

## 3. Перевірки змін після лабораторної роботи №7

Проміжна версія від 17 листопада 2026 року (`a4f4500`) додала керування вильотами й прибуттями, обхід небезпечних зон, розширену генерацію рельєфу та збереження нових станів польоту. Ці зміни дали сценарії для регресійної перевірки під час подальшої розробки. [Зміни в коміті `a4f4500`](https://github.com/dyxell1n/ATCsim/commit/a4f45008987f33fe966d12a129c19bdc00e026b5).

| Напрям | Що перевіряють автоматизовані тести |
|---|---|
| Керування рухом в аеропорту | Десять літаків вилітають по черзі зі спільної смуги, прибуття проходять через очікування й послідовні посадки. Закриття смуги на фінальній прямій спричиняє відхід на друге коло. |
| Обхід небезпечних зон | Автоматичне прямування до пункту призначення та ручна команда курсу враховують закритий повітряний простір. Літак очікує поза закритою зоною аеропорту та сідає після зняття обмеження. |
| Генерація карти | Однаковий сід відтворює початковий сектор. Для різних сідів перевірено зміну берегової лінії та різноманітність островів і прибережних ділянок. |
| Збереження сесії | SQLite відновлює схему очікування, час звільнення смуги, погодні зони та заплановані вильоти. Для сесій зі старою схемою визначається попередня версія рельєфу. |

## 4. Результати локальної перевірки

25 листопада 2026 року файл робочого процесу пройшов перевірку `actionlint 1.7.12` без зауважень. Для коду випуску на Windows із .NET SDK `10.0.401` виконано ті самі команди збирання й тестування, які задано в GitHub Actions. [Документація `actionlint`](https://github.com/rhysd/actionlint/tree/v1.7.12).

```powershell
dotnet build ATCsim.sln --configuration Release
dotnet test ATCsim.sln --configuration Release --no-build --verbosity normal
```

| Перевірена версія | Попередження збірки | Помилки збірки | Пройдено тестів |
|---|---:|---:|---:|
| `a4f4500`, попередня локальна перевірка змін від 17 листопада | 0 | 0 | 49 із 49 |
| `06750b5`, код випуску від 24 листопада | 0 | 0 | 70 із 70 |

У версії випуску тести додатково охоплюють імпорт і експорт сценаріїв та зіставлення результатів пошуку конфліктів у щільному трафіку з перевіркою всіх пар літаків. Збирання підтверджує компіляцію WPF. Відображення карти й взаємодія з її елементами потребують окремої перевірки у вікні застосунку.

## 5. Перевірка результатів на GitHub

Результати запуску після оновлення гілки доступні на вкладці **Actions**, а результат перевірки запиту на злиття до `main` відображається у вкладці **Checks**. У журналі завдання `Build and test (Windows)` можна перевірити результат етапів збирання й тестування. [GitHub Actions у репозиторії ATCsim](https://github.com/dyxell1n/ATCsim/actions).

До впровадження CI публічний API показав, що для `main` обов’язкові перевірки вимкнено. Автоматичне блокування злиття в разі помилки потребує окремого правила для `Build and test (Windows)` у налаштуваннях гілки. [Стан гілки `main`](https://api.github.com/repos/dyxell1n/ATCsim/branches/main), [налаштування захисту гілок GitHub](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule).

## Висновки

Налаштовано робочий процес GitHub Actions для збирання й тестування ATCsim у конфігурації `Release`. Локальна збірка коду випуску завершилася без попереджень і помилок. Усі 70 тестів пройшли. Результат хмарного запуску й застосування обов’язкової перевірки для `main` потребують підтвердження в GitHub.
